# AI Engineering Atlas — 交互色彩设计方案

## 1. 设计原则:双层视觉语系

平台内容分为两种性质,视觉上需要用不同的"语系"区分,避免读者混淆"这是必须遵守的规律"还是"可自由选择的策略"。

| 内容性质 | 判断标准 | 视觉语系 | 示例节点 |
|---|---|---|---|
| **规律类(Law)** | 客观事实,没有"选哪个"的决策空间,更像一条物理规律或工程铁律 | 白底卡片 + 左侧墨色/赭石色条强调 | 注意力分配曲线、上下文窗口限制 |
| **策略类(Strategy)** | 存在优劣权衡,读者需要根据场景做选择 | 白底卡片 + 优势/劣势双栏 + 进度条 | 最小化上下文 vs 分层上下文 |

**规则**:两种卡片都保持白底(不整体换深色背景,避免和平台其他页面的调性割裂),仅通过左侧色条 + 内容结构区分,不需要读文字就知道"这条是规矩,那条是选项"。

## 2. 纯色值表(暖调纸感配色)

平台放弃蓝紫色系(AI感/科技感过重,与"工程知识手册"的编辑气质不符),改用大地色系,整体基调更接近一份精心编辑过的技术文档。

| 角色 | 色值 | 用途 |
|---|---|---|
| 米白背景 | `#F5F0EB` | Background Light |
| 暖灰背景 | `#E8E2DB` | Background Warm |
| 墨色文字 | `#2A2A2A` | Text Primary |
| 深灰线条 | `#6B6560` | Lines / Secondary |
| 赭石橙主 | `#B85C3A` | Accent Primary |
| 赭石橙浅 | `#D4A574` | Accent Light |
| 赭石橙深 | `#8B3D2A` | Accent Deep |
| 苔绿辅 | `#6B7B5E` | Status / Secondary |
| 苔绿浅 | `#8B9A7E` | Status Light |
| 陶土色 | `#A67C5B` | Tertiary / Warning |

**权重层级**:赭石深 → 赭石浅 → 苔绿 → 暖灰

**使用注意**:赭石橙浅 `#D4A574` 与陶土色 `#A67C5B` 明度、色相接近,不要在同一组对比元素中同时使用(比如同一张图里一个当强调色、一个当警告色),容易分不清谁是谁。两者需要错开使用场景。

## 3. 色彩语义系统:结构色块与位置色阶

### 3.1 核心逻辑

凡是"内容在序列中的位置会影响效果"这一类知识点(如注意力曲线的头部/中部/尾部),不再用多色相拼接,而是**用同一个色相(赭石橙)的深浅变化**表达位置/权重层级——深浅本身自带"轻重"的直觉,比多色相跳跃更克制,也更贴近权重高低这个语义。

### 3.2 注意力曲线色阶定义

| 位置区间 | 语义 | 色值 | 用途 |
|---|---|---|---|
| 头部(0%-15%) | System Prompt / 核心指令 / 强制约束 | 赭石橙深 `#8B3D2A` | 曲线起点、Prompt 结构色块、图例圆点 |
| 中部(15%-85%) | 检索文档 / 背景信息(低注意力区) | 赭石橙浅 `#D4A574` | 曲线中段、Prompt 结构色块 |
| 尾部(85%-100%) | 用户 Query / 输出格式指令 | 赭石橙深 `#8B3D2A` | 曲线终点、Prompt 结构色块 |

**曲线配色**:头部深→中部浅→尾部深,首尾同色、中部浅色,直接呼应"两端权重高、中间权重低"的 U 形规律,不需要三种色相硬凑一个渐变。

**修正要求(基于上一版反馈)**:
- 曲线必须是单调下降(头部→中部)+ 单调上升(中部→尾部)的干净 U 形,禁止因插值平滑度(tension)过高产生中部"回弹驼峰"的视觉假象。建议采样点数 ≥ 20,tension ≤ 0.35。
- 曲线上的文字标注(如"低注意力区")需与曲线路径保持垂直间距 ≥ 24px,或加不透明背景垫底,确保任何位置都可读。

### 3.3 通用色彩分配原则(适用于所有诊断/分类类图表)

- 每张图优先用**单一色相的深浅层级**表达强弱/权重,而不是多色相拼接
- 确实需要区分"类别"(而非"强弱")时,才引入第二个色相(比如轨道类节点用苔绿 vs 赭石橙)
- 中性/结构性元素(标题、分隔线、坐标轴)统一用深灰线条 `#6B6560`,不占用语义色

## 4. 交互态色彩规则

### 4.1 轨道类节点(如 RAG 离线/在线双轨道)

| 轨道 | 默认态 | 选中态 | 说明 |
|---|---|---|---|
| 离线建设期 | 苔绿 `#6B7B5E` 图标 + 灰色边框 | 苔绿边框 + 苔绿浅底 | 选中态继承轨道色 |
| 在线服务期 | 赭石橙主 `#B85C3A` 图标 + 灰色边框 | 赭石橙边框 + 赭石橙浅底 | 同上 |

**核心规则**:选中态颜色必须继承所在分组/轨道的语义色,不能全局统一用一个"选中色",否则会削弱轨道色本身的辨识度。

### 4.2 悬浮(hover)与点击反馈

- Hover:边框从 `--border` 升级为 `--border-strong`,背景轻微加深(`--surface-1`),不使用阴影
- 点击/激活态:`scale(0.98)` 轻微缩放反馈,过渡时长 150-200ms
- 页面/轨道切换(如 A5→B1 离线转在线):允许更明显的过渡效果(如色相渐变闪过),强化"发生了关键跳转"的心理感知

### 4.3 状态色(与语义色分开管理)

以下状态色为**功能色**,不与上述"位置/类别语义色"混用,专门用于系统反馈,保持整体色调统一(不使用鲜艳的系统红绿):

| 状态 | 色值 | 用途 |
|---|---|---|
| 优势/正确 | 苔绿辅 `#6B7B5E` | 优势标记(✓)、完成状态 |
| 需要注意/劣势 | 陶土色 `#A67C5B` | 劣势标记(✗)、警告状态(注意与赭石橙浅错开使用场景) |
| 强调/默认 | 赭石橙主 `#B85C3A` | 提示性说明、非轨道类节点的默认强调色 |

## 5. 卡片背景与强调条规范

- **规律类卡片**:白底(`#F5F0EB` 或 `--surface-2`),左侧加 4px 墨色 `#2A2A2A` 或赭石橙主 `#B85C3A` 色条,不整体换深色背景
- **策略类卡片**:白底,配优势/劣势双栏 + 效果对比进度条(进度条使用赭石橙主作为强调色)
- 全平台统一使用米白/暖灰纸感背景,不出现纯白或深色卡片,保持"技术文档"的编辑气质

## 6. 命名与复用建议

建议在设计系统 / CSS 变量中固定以下命名,方便团队协作时直接引用,不用每次口头对齐:

```
--bg-light: #F5F0EB       (米白背景)
--bg-warm: #E8E2DB        (暖灰背景)
--text-primary: #2A2A2A   (墨色文字)
--text-secondary: #6B6560 (深灰线条)
--accent-primary: #B85C3A (赭石橙主)
--accent-light: #D4A574   (赭石橙浅,用于低权重/中部)
--accent-deep: #8B3D2A    (赭石橙深,用于高权重/头尾)
--status-positive: #6B7B5E (苔绿辅,优势/正确)
--status-positive-light: #8B9A7E (苔绿浅)
--status-warning: #A67C5B  (陶土色,警告/劣势)
--track-offline: #6B7B5E   (苔绿,离线建设期)
--track-online: #B85C3A    (赭石橙主,在线服务期)
```

后续新增知识节点时,先判断属于"规律类"还是"策略类",两者都用白底 + 色条区分即可;涉及"位置/顺序影响效果"的知识点,优先复用 `--accent-deep/light` 的深浅层级,不要重新发明多色相渐变。
